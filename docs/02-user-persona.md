# 02 — 用户画像

## 角色一：招聘 HR

### 基本信息

- 姓名：林悦（示例）
- 角色：招聘专员 / HRBP
- 企业规模：50-500 人
- 招聘量：每月 3-10 个岗位，每个岗位收 50-300 份简历

### 日常工作

```
早上打开招聘网站 → 收简历 → 筛选 → 转发业务负责人 → 约面试 → 跟进
```

### 核心痛点

| 痛点 | 描述 |
|------|------|
| 简历太多 | 一个岗位收 200+ 份简历，90% 不匹配，但必须看完 |
| 信息散乱 | 候选人信息存在于邮箱、微信、Excel、聊天记录里 |
| 筛选依赖经验 | 快速判断一个候选人是否合适，经验不足的 HR 容易漏掉好的人 |
| 业务沟通成本高 | 要把候选人信息转述给 Hiring Manager，来回效率低 |
| 历史候选人浪费 | 上次淘汰的候选人，下次开新岗位时找不到、记不住 |

### 目标

1. 上传简历后自动提取关键信息，不用手动录入
2. 快速看到候选人与岗位的匹配程度和原因
3. 候选人信息结构化存储，后续可搜索复用
4. 给 Hiring Manager 发候选人时不需重新整理信息

---

## 角色二：Hiring Manager（业务负责人）

### 基本信息

- 姓名：陈磊（示例）
- 角色：产品总监 / 技术负责人
- 场景：团队有空缺，需要招人，但不是专职招聘

### 核心痛点

| 痛点 | 描述 |
|------|------|
| 不想看大量简历 | HR 发来 30 份简历 PDF，没时间逐份看 |
| 不知道推荐理由 | HR 说"这个人不错"，但不知道具体哪里匹配 |
| 判断标准不一致 | HR 筛选时可能误解了岗位的实际需求 |
| 面试准备不充分 | 面试时对候选人的背景了解有限，问题针对性不够 |

### 目标

1. 只看 HR 筛选后的候选人，每人一页卡片，信息精炼
2. 一目了然地看到匹配点和风险点
3. 可以对候选人标注评价，反馈给 HR

---

## 用户场景矩阵

| 场景 | HR | Hiring Manager |
|------|-----|----------------|
| 创建岗位 | 上传 JD → 确认 AI 生成的岗位画像 | — |
| 筛选候选人 | 上传简历 → 查看匹配报告 → 初筛 | — |
| 评估候选人 | — | 查看候选人画像 + 匹配分析 → 标注评价 |
| 面试准备 | 打印候选人画像 | 查看画像中的项目经验、优劣势 |
| 人才复用 | 搜索历史候选人 → 发现匹配人选 | — |

## 两个角色的信息需求差异

| 维度 | HR 需要 | Hiring Manager 需要 |
|------|--------|-------------------|
| 信息深度 | 快速筛选用，关键信息突出 | 深度评估用，项目细节充分 |
| 匹配视角 | 硬性条件优先（年限、技能） | 软性能力优先（项目匹配度、潜力） |
| 操作 | 批量处理、搜索 | 单个深度阅读、评价 |
