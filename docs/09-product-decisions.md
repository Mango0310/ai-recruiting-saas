# 09 — 产品决策记录

记录 V1 设计 + 开发过程中的关键决策及理由。

---

## 决策 1：为什么不用评分数字（86%）？

**背景**：大多数 AI 招聘工具输出"匹配度 86%"。

**选择**：展示 Match Report（匹配优势 + 待关注点 + 面试建议），用星级（1-5）作为感性综合判断。

**理由**：
1. 匹配度百分比没有可信的数学依据——LLM 不是评分模型
2. 百分比容易造成"AI 做决策"的错觉
3. 定性的 Match Report 信息量更大——告诉 HR 为什么推荐、面试问什么

---

## 决策 2：面试问题为什么不能问"请举例说明你缺少的经验"？

**背景**：第一版面试问题基于缺口逐条生成，出现了"缺少 SaaS 经验，请举例说明"这种无法回答的问题。

**选择**：面试问题分 4 个维度生成——能力深度、可迁移能力、角色匹配、协作能力。缺经验不问经验，问底层思维。

**理由**：
1. 让人举例他没有的经验是无效问题
2. 面试的目标是评估候选人能不能做这个工作，不是验证简历
3. 可迁移能力（学习速度、底层思维、问题拆解）才是面试真正该考察的

---

## 决策 3：为什么 AI 要先追问再生成岗位画像？

**背景**：大多数系统输入 JD → 直接输出画像。

**选择**：HR 填基本信息 → AI 发现缺口并追问 → HR 回答 → 完整画像。

**理由**：
1. 业务方给的原始需求往往信息不全（"帮我招个产品经理"）
2. AI 直接生成会编造信息
3. 追问机制的定位是"整理需求"，不是"编需求"

---

## 决策 4：为什么 HR 和员工入职登记分开？

**背景**：入职时 HR 需要填工作信息（岗位/薪资/试用期），员工需要填个人信息（身份证/银行卡/紧急联系人）。

**选择**：HR 填工作信息 → 生成唯一链接 → 发给员工自助填写。

**理由**：
1. HR 不应该看到员工的银行卡号、紧急联系人等隐私信息
2. 员工自助减少 HR 的数据录入工作量
3. 链接机制天然支持"先发 offer，入职当天再填信息"的场景

---

## 决策 5：录用后为什么分两个库？

**背景**：录用确认后，有的候选人入职了，有的放回备用。

**选择**：Pipeline 末尾分叉——合适的人进"入职员工库"（Employee 表），待定/不合适的人进"储备人才库"。

**理由**：
1. 入职员工需要台账管理（试用期、转正、社保），和普通候选人的需求完全不同
2. 储备人才库用于未来搜索复用（"上次那个差点合适的，现在新岗位开了找他"）
3. 两个库的数据结构不同：Employee 有入职日期/试用期，Candidate 只有岗位申请记录

---

## 决策 6：为什么用 Hiring Brief 而非直接解析 JD？

**背景**：很多招聘系统只解析 JD 文本，忽略了"为什么招人"这个关键信息。

**选择**：招聘需求创建时收集三个额外维度——招聘原因、团队现状、入职 3 个月目标。AI 生成 Hiring Brief。

**理由**：
1. 同一个 JD 在不同公司含义完全不同（"AI 产品经理"在电商和医疗公司是两个人）
2. 招聘原因决定了评估标准的侧重点（补缺 vs 扩张 vs 转型）
3. 入职目标让岗位画像和评估框架更有针对性

---

## 决策 7：为什么人才库搜索不用 SQL 全文检索？

**背景**：候选人的技能、经历在 JSON 字段里，SQLite 不支持 JSON 全文搜索。

**选择**：全 Python 侧过滤。获取所有候选人 → 按关键词/技能/状态在 Python 中过滤。

**理由**：
1. V1 数据量不超过几百条，Python 内存过滤毫秒级完成
2. 不需要引入 Elasticsearch 或 pgvector
3. 逻辑简单、可读、易调试
4. Phase 2 上 PostgreSQL 后再切到 `tsvector` 或 `pgvector`

---

## 决策 8：为什么候选人列表要展示 AI 判断依据而非裸分？

**背景**：第一版候选人列表每行只显示名字 + 星级。

**选择**：升级为"AI 评审台"——每张卡片展示匹配优势 + 待关注点 + A/B/C 级 + 星级。

**理由**：
1. HR 打开页面的第一眼应该看到"为什么"，而不是"多少分"
2. 评分只是辅助，判断依据才是核心
3. 如果你只展示分数，HR 没法判断 AI 是否可靠——展示依据让 HR 自己判断

---

## 决策 9：为什么 AI 分析结果标上"仅供参考"？

**背景**：AI 招聘工具常被误解为"AI 在做决策"。

**选择**：Match Report 顶部 Hero 卡片旁标注"AI 分析仅供参考，不替代 HR 最终决策"。

**理由**：
1. 产品价值观：辅助而非替代
2. 合规风险：不能给人"系统自动淘汰候选人"的印象
3. 面试时加分——面试官会问"你做的 AI 决策边界在哪"，标注了就是最好的回答
